# 共享目录页面预算合同草案 v0.1

状态：设计草案，未实现，未验收。依据 [SPEC M2](specs/SPEC-speed-token-efficiency-v1.md)。在 G1 通过前不进入 M2 正式实施，G2 通过前不启用共享目录自动采集。

## 现有企业路径的实际口径

- `runs._claim` 在锁定 run 行的事务中，根据 `page_limit_total - pages - reserved_pages` 预留企业剩余页面额度；并发企业竞争同一个 run 计数。预留保存在 job 输出和 run 统计中。
- `fetch_company` 对每次页面尝试记录一个 page，成功和 WebError 都加入 pages；复用已保存页面无需新抓取。正常结束 `_complete` 以 `len(pages)` 结算，释放本次预留。企业重试产生的新页面尝试再次计数。
- `safe_http` 的一次页面尝试可能产生多次重定向 HTTP 发送以及 robots 请求；这些物理请求通过独立 observation 记录，不等于页面计数。查阅实时观测中 `dispatched` 可为 true、false 或未知，开始记录写入失败时不发送。
- 企业中断恢复 `_reclaim_expired` 按物理开始记录保守计算，观测缺失或无法归属时消耗剩余企业额度；不能以正常结算下的页面次数替代这一恢复上界。

这些是对源码现状的描述，不等于共享目录具备同等预算或恢复能力；旧 run 保持原算法和历史计数。

## 拟议的新 run 合同 `shared-page-budget-1`

每次目录列表或企业详情**页面尝试**在派发前占用一个页面预留；单个列表页无论包含多少企业，只占一次 run 页面预算。详情页另外计入 run 总预算与相应企业预算。成功、被拒、超时或其他失败的已开始尝试均消耗一个页面单位；未发送前明确取消且能证明没有开始的预留可释放。robots、DNS、HTTP 重定向 hop 和物理重试各自记录观测与实际尝试，但不再把其个数直接加为页面单位；真正重新开始的页面尝试重新预留。以上是拟议口径，实际实现必须逐项对照企业路径、失败／中断语义，不能据此改写旧 run。

缓存只允许 run 内使用；记录原始采集时间、来源和复用，不伪造访问。是否计页面由本合同中的明确缓存命中事件决定，不把独立的 robots 缓存等同页面缓存。跨 run 默认禁用。

run 行锁保护已消耗与所有活跃预留；企业与目录派发共享同一事务边界，始终保证 `consumed + reserved <= frozen_total`。新账本需唯一约束 `(run_id, operation_key, attempt)`，记录来源、URL、页面类型、企业（适用时）、输入哈希、预留、发送观测关联、结算、时间与结果；同操作键同输入重放结果，不发送也不重扣，不同输入冲突。暂停、租约和发送前防护必须保持原约束。无法确认是否发送时保守保留相应预留并显式报告 unknown，不能自动释放或盲目重试。

页面预算和物理请求观测是两个相关但不同的账本；每次物理发送仍必须经现有 URL/IP、robots、域名限速、退避、重定向边界和持久化观测，不依赖 Agent 外部工具代替核心预算。预算耗尽停止派发并保留检查点。对缺少该冻结合同的旧 run 和外部未经统一记账的抓取路径安全拒绝目录自动采集。

## 升级、验收与回滚前置项

需在真实 PostgreSQL 的隔离数据库中验证同页多企业、详情页、缓存、重试、重定向、最后预算争抢、企业与目录竞争、各崩溃边界、观测故障、暂停和幂等重放；与实际发送记录交叉核对。迁移前备份数据库及引用工件，测试升级、旧 run 的读取续跑导出及恢复；旧版本无法安全识别新 schema 或新 run 时禁止直接回退，采用验证过的隔离恢复路径。仅在 G2 通过后声明能力并允许 M3 试点。
