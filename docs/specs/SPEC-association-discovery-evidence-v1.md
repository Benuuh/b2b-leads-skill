## 1. 问题与目标

美国货代任务反映出：候选企业可能存在，但国家证明的字面识别、JS 页面、网络拦截与搜索不可用会让取证停滞。现有 `country_supported` 主要匹配国家两位码和 `pycountry` 名称；是否造成某个具体批次的待核或排除，应以该批次保存的条件、观察与判定复现，不能将所有未命中一概称为不符合。现有 Skill 已提倡协会和目录，但缺少保证「实际尝试地方目录、逐条留痕、根据字段补证」的可验收流程。

目标是在不放宽用户资格、主体绑定、证据和渠道要求的前提下：

1. 让全国、州、省、市及港口等地方行业协会目录成为主动发现渠道，尽可能从高信息密度页面批量获取候选及可核验事实。
2. 修复有证据的国家表达未识别问题，区分经营地、总部、注册地与服务范围。
3. 缺失正文时使用安全、有预算的渲染回退；搜索或域名不可用时，切换可用公开来源并报告原因。
4. 按阶段记录瓶颈，以实际合格交付和人工抽检衡量效果；不能靠降低标准或目标制造提速。

非目标：保证找到指定数量；默认采购数据或绕过登录、验证码、访问限制；把协会会员自动视为合格货代；悄悄改变已冻结批次的资格规则；把搜索摘要当作证据。客群分析及确认仍遵循关联规格，`brief` 保持离线。

## 2. 执行流程：协会目录优先的多来源发现

### 2.1 来源查找和选择

确认后的研究阶段先根据国家、行业、经营范围及地区检索可公开访问的全国性协会、州/省/市及港口地方协会、行业商会、展会名录和可用的官方登记机构；**地方协会不是仅在搜索失败时才尝试**。如已知相关目录入口，可直接访问；否则使用当前实际可用的搜索或页面工具寻找。不得编造协会、网址、会员数或目录可用性。没有可用搜索时，从已知且可核验的入口或其他可访问来源继续；确实找不到可用入口则记录原因和检查点。

为每个候选来源记录：名称、入口 URL、组织或目录身份的核验依据、目标国家/地区及行业相关性、最近检查时间、可访问状态、是否公开、预计字段、已查看的页数与发现数。优先选与目标行业及地区匹配、公开且能直接提供企业名、地址、业务或渠道字段的目录；全国和地方目录互补，重复项去重；不按来源名称或排名预设其一定可靠。明确区分「未尝试」「无法访问」「已查看无相关项」。

当行业存在可访问的地方目录，至少尝试一个与目标地区相关的地方目录；不存在、未找到或被限制时记录原因，不得伪称已覆盖。全国和地方目录、替代公开来源可按效率动态调整顺序，已找到足够可处理候选时无需无目的遍历全部地区。

### 2.2 列表到资格

1. 目录列表页先批量识别企业名、会员详情链接及同一条目明确可见的字段；不把相邻条目的地址或渠道拼到一起。来源仅是线索时进入发现池，不计为已准入或合格。
2. 若列表或详情页对某个企业明确呈现其地址、业务描述或公开企业渠道，为每个字段生成独立观察：主体、实际值、原文摘录、完整 URL、来源类型、采集时间与方法。协会页面可以证明其明确写出的事实；协会会员身份本身、目录分类或企业名称不能自动证明所有资格条件。
3. 仅补缺失的主体、国家、业务和渠道；目录已提供满足证据政策的观察时不强制重复打开官网。官网归属仍须独立核实；不能因公司名相似、共用域名或目录里的链接就无条件归并不同实体。搜索摘要只作发现线索。
4. 通过现有 `validate-input` 预检后，按现有 `advance` 流程提交首批和后续有界 chunk；保留来源、原始观察及检查点。不得声称新增入口或数据格式已存在。候选去重沿用现有身份与抑制规则；目录多次出现同一实体不增加唯一候选数。
5. 有满足规则的业务邮箱、电话或表单即按用户确认的 `any/all` 判断；不能因为邮箱缺失就自动降级为电话，或把普通联系页面当表单。

**共享页面计费**：列表页一次实际加载产生一次页面观察和计数，不按列表中的企业数重复计页；独立详情页各计一次。无论通过目录、普通页面或渲染获取，都须计入同一 run 的总页面与时间限制，并记录请求/物理尝试；单企业页面限制按归属该企业的详情及官网访问计算，来源列表计入批次总量而不伪造为某一家访问。复用同一页时保留条目级主体绑定及来源引用。对确认前的小样本诊断单独记录时间和请求，不纳入尚不存在的 run 预算。此计量模型需实现并验收后才能启用；预算无法准确计量时停止该自动采集路径并说明限制。

## 3. 国家证据与规则版本

### 3.1 判定契约

国家仍规范化为 ISO 3166-1 alpha-2；输入原文不改写。新规则在目标主体明确、语义明确且原始来源满足当前证据合同的前提下，识别 `United States`、`United States of America`、`USA`、`U.S.`、`U.S.A.` 及明确国家语境中的 `US`。标点、大小写和边界应有测试；不能把普通代词 `us` 当成国家，也不能将未消歧的 `CA` 当作加州或加拿大。

美国州名、州缩写、邮编等仅在**可验证的完整地址上下文**中辅助识别：例如目标企业的美国街道地址、城市、州及有效格式邮编同时出现，且无冲突时，可支持该企业存在美国经营地点；仅凭一个州名、缩写或邮编不足以通过。州/邮编组合和地址规则需使用版本化数据并覆盖歧义；未能充分消歧则 `unknown`。不从电话区号、`.us` 域名、客户地址、运输目的地或覆盖范围推断企业所在地。

经营地、总部、注册地各自判定：目标主体的当地办公室可支持经营地，不能自动证明总部或注册地；后两者需要各自明确的语义和可接受来源。集团、分支、合作伙伴或客户地址不能自动转给目标实体；历史、否定和已关闭地点不能视为当前事实。保留 URL、主体、原文、采集时间、来源类型、标准化值、规则版本和解释；原文没写 `US` 时不得合成含 `US` 的证据摘录。证据不足为 `unknown`，冲突为 `conflict`，仅有足够的相反事实才 `fail`。协会、官网和官方登记均按来源政策及具体事实核验，来源类型不是事实本身。

### 3.2 规则冻结与兼容

计划为新语义引入独立规则版本，例如 `b2b-policy-3`，编号仅为设计占位，以实际发布契约为准。现有代码有全局 `RULE_VERSION`，计划中写入版本号本身**不等于**运行时已按该版本分派；实现必须让预检、准入、补证、重评、处理、导出及交付选择均根据 run 冻结版本调用同一版本规则。新 run 冻结新版本；旧 v2 run 继续使用 `b2b-policy-2`，v1 按现有 v1 语义处理。缺少旧版本实现或无法识别历史 run 的版本时，应阻止会改动判定的操作并明确报错，允许安全读取和导出已有快照，不能静默套用新规则。确认规格上线时，生效规则版本纳入其确认范围。

本期不实现跨版本自动迁移；旧 run 的 `reassess` 仍按其冻结规则运行。若要对旧证据应用新规则，须另立方案明确用户授权、原证据复用、对比报告、新旧 run 身份、计数与导出隔离，以及无法复用的情况；不得覆盖历史结果或承诺能一键恢复旧批次。回滚前验证实际旧版发布包与新旧 run 的读写兼容，不能因 schema 未变推断规则兼容。

## 4. 页面读取和故障退路

### 4.1 分层获取

先复用已保存的有效观察，再按缺失事实访问公开目录或普通 HTTP 页面；只有正文不可用且仍需该事实时才考虑 JS 渲染。静态正文充足时不重复渲染。渲染仅处理允许公开访问的页面，限制页面数、域名请求速率、并发、单页等待及单次总时长；通过统一预算和观测层计数。浏览器发出的导航、重定向和子资源请求均须经过等效的公网地址验证、robots、域名限流和请求观测；不能提供这些保障时禁用自动渲染并报能力不可用，不得绕过现有网络防护。渲染文本必须可追溯到实际页面和采集时间，不执行登录、不解验证码、不读取本机敏感资源。

渲染预算不能扩大现有上限；达到上限即停止，保留待核。目录本身是 JS 页时也使用同样的策略。页面工具与执行核心若拥有不同网络路径，应分别记录访问结果，不能把一个路径上的失败说成全网不可达。

### 4.2 失败分流

| 情况 | 处理 |
|---|---|
| 搜索不可用 | 优先尝试已核验的相关协会、公开目录或官方登记入口；没有入口则暂停、保存检查点并说明缺口。 |
| 静态页无正文 | 识别为疑似渲染问题；在能力和预算允许时有限回退，否则待核。 |
| DNS/超时/网络拦截 | 按既有策略有限重试，记录具体类别；尝试可用的允许来源，不将失败当作事实否定。 |
| 403、登录、验证码、robots 拒绝或未知 | 不绕过；停止该来源并寻找可公开访问的替代。429 遵守退避与熔断，不靠换路径继续打同一来源。 |
| 目录只有名称 | 仅作候选发现，不自动支持国家、业务或渠道；按缺项补证，补不到保留待核。 |
| 多来源冲突 | 保留观察与冲突，进入待核；不能由后来的猜测覆盖。 |
| 来源和工具均不可用 | 保存检查点，暂停该批次并如实报告；不反复手工逐页空转。 |

## 5. 观测、测试与验收

按 run 和来源记录：尝试与可访问来源、地方协会尝试情况；发现条目、去重后候选、预检可准入、实际准入、待核、排除与合格可交付；国家、业务、主体和渠道缺项；静态获取/渲染的尝试、结果和耗时；DNS、超时、403、429、robots、JS 空正文与工具不可用；页面数、请求数和各阶段耗时。每个指标定义统计口径和重试去重规则，缺数据为未知，不按零填充；不得将请求数当作页面数或把发现数当作合格数。导出质量报告摘要和可追溯来源，但不暴露客户排除名单。

| 编号 | 发布验收 |
|---|---|
| AC-01 | 可控测试中，全国、地方协会列表及详情页均能进入发现流程；地方目录可用时实际尝试，不可用时有状态与原因；同页多个主体不串字段。 |
| AC-02 | 对每项事实核验来源、主体、原文及时间；仅有会员身份、名称或分类的记录不能自动合格。官网已知事实与目录事实可复用，官网归属独立核验。 |
| AC-03 | 新国家规则覆盖 §3.1 正反例及国家角色；各路径输出一致、可追溯，`unknown`/`conflict`/`fail` 符合证据语义。既有其他国家案例不回归。 |
| AC-04 | 旧 v1/v2 run 在升级后的预检、处理、补证、重评和导出维持冻结语义与历史计数；新 run 使用新版本。禁用旧规则时安全失败；跨版本迁移不会隐式发生。数据库测试不可用时不能以跳过算通过。 |
| AC-05 | 静态、JS、重定向、DNS、超时、403、429、robots 与不可访问场景均验证限额、分类和待核；渲染所有网络请求遵守等效防护，不能满足时回退禁用。 |
| AC-06 | 列表页多企业只计一次批次页面，详情页逐次计量；复用、重试、并发、进程中断与恢复不漏计、不重复准入，保持既有幂等及预算语义。 |
| AC-07 | 真实任务试点至少使用 30 个去重候选，覆盖可访问的地方协会及至少一种其他公开来源；记录样本如何选取、时间、工具、环境、限制及全部阶段漏斗。若环境不足 30 家如实停止并标注验收未完成，不得凑数。 |
| AC-08 | 对同一固定证据样本分别运行旧/新规则并人工逐条标注国家与主体真值，报告通过、未知、冲突及误判变化；新规则不能新增人工确认的国家/主体误通过。人工抽检所有新增通过记录及其证据，未解决误通过则阻止发布。 |
| AC-09 | 在相同目标、规则口径及采样条件下记录旧/新发现至交付耗时、单位时间合格数、人工逐页操作数及失败分布；若环境或样本不具可比性明确说明，不能据此宣称提速。未达到改善时保留诊断结论并修正方案，不把数量增长单独作为成功。 |
| AC-10 | 与确认规格一致：执行前披露已知能力和未测限制，`brief` 保持离线；确认后不得擅自调整目标、证据或渠道规则。 |

## 6. 实施顺序与交付门槛

1. **复现与基线**：选取实际批次中可复用、脱敏的失败样本，分别复现 `USA` 等国家表达、主体绑定、JS、网络及搜索问题；记录规则版本和状态，建立人工真值及耗时基线。
2. **规则版本与国家取证**：先实现可实际执行的版本分派与旧批次兼容，再实现国家标准化和语义检查；完成 AC-03、AC-04、AC-08 后才能用于新批次。
3. **协会优先发现**：完善 Skill 指南、来源台账、列表到字段观察、去重和检查点；实现共享页面预算与观测，完成 AC-01、AC-02、AC-06。先支持现有合法工具，不能承诺所有目录都能自动抓取。
4. **安全渲染与故障处理**：只有统一网络防护、预算与观测均能覆盖浏览器请求时才启用；否则将渲染作为不可用能力披露，并继续其他允许来源。
5. **真实试点与发布**：完成适用验收、比较结果和回滚演练，明确已实现和未实现项，更新 Skill、证据合同、控制器、能力声明及发布记录；具体产品版本在确定发布范围后决定。本文件不授权跳过测试、规则冻结或现有限额。
