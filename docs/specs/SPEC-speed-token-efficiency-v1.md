# SPEC：搜客速度与 Token 成本优化

日期：2026-11-03｜规格版本：1.0｜状态：最终实施规格，功能尚未实施

**强制顺序：真实任务成本基线 → 自动整理和校验候选证据 → 统一共享目录预算 → 目录批量采集。** 每个阶段须通过本规格对应门槛才进入下一阶段的正式实施或试点；可提前做无副作用的设计和测试夹具。共享目录预算未通过验收前，不启用自动共享页面采集。真实样本或 token 不可获取时可以完成受控开发，但对应真实成本验收保持未通过，不得宣称达到降本目标。

## 1. 目标与基线

在相同客群、数量、证据与渠道要求下，提高每小时可交付企业数，降低每家可交付企业消耗的 Agent token，并缩短首批交付时间。质量、来源可追溯性、预算、去重、排除名单和恢复能力是验收前提。

已安装 Skill/核心 2.2.0，规则 `b2b-policy-2`；工作区存在未发布的 2.3.1 开发修改，不能把源码能力说成已安装能力。以实际入口 `capabilities` 和发布清单复核版本。2.2.0 受控基准中六家一批中位数从 4.435 秒降至 1.312 秒，三命令合一的中位数从 2.736 秒降至 1.169 秒；都是特定合成场景，不代表真实任务速度。当前没有可比的真实端到端和 token 基线。

不重复建设已有的 `advance`、首批 5 家/后续 10–20 家、4 worker 上限、缺项抓取、已存证据复用、最小充分停止和解析复用。优先减少 Agent 需要阅读、搬运和重复处理的信息。

## 2. 方案与优先级

### P0：可观测基线与成本归因

每次试验记录版本、配置 hash、目标、来源、样本选择、工具、环境、开始/结束和暂停时间；记录首个、首 5 家、每 10 家及最终可交付结果时间、最终合格数、缺项和失败分布。分开记录发现、搜索/页面等待、证据整理、预检、处理、数据库/投影和导出；并发阶段不得相加当总墙钟。计量实际搜索调用、页面打开、物理 HTTP、工具返回字符数、Agent 轮次以及可获取的输入、输出、缓存 token。不可获取的指标为 null，并记录来源；字符数只能作为流量代理，不能冒充 token。

主指标为有效可交付数/活动小时、首 5 家墙钟时间、总输入加输出 token/有效可交付数；分别列出缓存 token 和计费口径，不重复相加。零交付时该比值标记不可计算，同时报告总成本、漏斗和原因。若平台只能获得整轮 token，标明范围，不能声称精确分摊到单次调用。禁止记录排除名单或凭据。

### P1：本地证据暂存和精简上下文

新增本地、有界的候选/证据暂存工件，以 run、来源 URL、采集时间、主体、原文摘录、字段和值关联；完整证据持久保存，模型通常只接收候选 ID、必要字段、短摘录、缺项和引用。对同页多个主体按条目隔离，不凭相邻文本拼接。摘录必须足以支持事实；不充分则按需读取原文，不用摘要替代证据。限制单次返回记录数和字节数，提供游标和按 ID 查看；错误、冲突和失败原因不可因压缩被隐藏。

增加离线草稿转换/校验器，把已观察到的结构化字段整理成现有输入合同、生成稳定 chunk 和哈希；确定性处理只负责格式、来源引用、规范化及校验，不能凭名称、目录类别或搜索摘要自行断言资格。整块预检失败时返回错误索引和可提交子集路径，原子提交及同键重放语义不变；文件中不得引入臆造观察。断点续做只加载简短检查点与相关缺项，不反复把整个历史输入放进模型上下文。暂存文件遵守现有保存、访问和清理策略。

### P1：发现与取证按批次流水化

Agent 批量查找高信息密度的公开目录，先识别候选及可见字段，按缺项集中打开相关页面；必要资格事实及官网归属就绪后交 `advance`，让核心补渠道。处理命令运行时仅在执行环境确实支持并发的情况下继续独立发现，避免承诺后台进程长期存活。对无法证实的企业进入缺项队列，按来源和缺失字段合并后续查询；对明确限制、熔断或重复失败停止空转。搜索摘要仅用于发现。

计划增加按来源和缺项的简短优先队列，按已观测的有效率和成本排序，并保留来源多样性；排序不改变资格规则。首次选 5 家，后续 10–20 家为基线，仅在对照测试后调整，兼顾首批延迟、整块拒绝率和处理吞吐。

共享目录自动采集依赖统一预算预留、持久化、恢复、来源及请求计量；目前不可用，不能声称已经实现。静态获取不足时 JS 渲染仍不可用，直到浏览器全部请求具备等效网络防护和统一预算。国家别名、总部/经营地语义及规则版本运行时分派按协会目录规格单独完成；旧 run 沿冻结规则处理，不能用性能优化绕过其验收。

### P2：控制器增量响应与按需详情

评估给 `advance`/`status` 增加版本化精简响应：run 和操作 ID、修订、进度增量、缺项聚合、失败类别、快照引用、分页游标。保留完整详情的显式读取路径和原有默认合同；若无修订变化仅返回未变化状态。记录响应字节和模型读取量，比较效果后再默认启用。受限输出不得掩盖异常、预算、熔断或中断恢复信息。

评估基于证据指纹的跨命令复用：键至少覆盖主体、来源内容与时间、事实、完整冻结政策、规则版本与有效期；过期、撤回、冲突、主体变化或政策变化立即失效。复用不改变原始采集时间、来源或证据新鲜度；未能证明正确失效时不启用。跨 run 复用须隔离权限、排除名单和企业身份；先离线等价测试，再考虑实际使用。

### P2：按测量结果处理本地热点

针对数据库聚合、投影、快照和 Excel 编码分别计时；仅在证明其为瓶颈后做批量查询、增量投影或快照参数调整。已有记录中 15 家导出约 6.4 秒，200 家未测，不能据此推断线性增长。并发仍受冻结配置、单域限速、robots、重试、预算和熔断约束；不简单提高 worker 或降低证据要求。

## 3. 实施顺序与验收

1. **基线**：先建立可复现受控样本与记录协议，再在明确的真实任务中测至少 30 个去重候选；若无法达到如实报告，不算通过。原始数据脱敏保留、注明工具可观测范围。
2. **暂存和草稿工具**：以固定页面样本对照逐字段主体、原文和来源；测试长页面、同页多公司、冲突、失效、非法输入、分页、幂等重放、中断恢复、名单隔离和缺失原文。只有结果等价且错误可见才能进入试点。
3. **批次流程及精简响应**：固定样本测首批时间、有效吞吐、读取量和块拒绝率；检查不能丢失异常、恢复信息或证据。不同条件下的搜索不可直接视为严格 A/B，固定捕获样本用于可复现对比，在线试点单独报告来源和环境变化。
4. **质量和成本验收**：同样的政策、预算、候选及证据下，对照旧版和新版的可交付集合、身份、渠道、证据引用及未知/冲突状态；人工抽检同一分层样本以及全部新增通过项，发现误通过则阻止发布。无可比 token 数据时成本验收未完成。
5. **发布**：先独立测试、完成冻结发布与安装验证，记录版本、测试、基线和回滚；已有 run 不修改冻结设置和历史口径。未完成的关联规格单列，不得标为已发布能力。

试验目标（假设，须基线后确认）：固定样本上每家可交付企业 token 降低至少 25%，首 5 家墙钟时间降低至少 15%，有效交付吞吐不下降；对照数据不足或目标未达成就报告实际结果和瓶颈，不用合成测试推断线上收益。分别披露输入、输出和缓存 token 变化，避免把上下文压缩导致的额外重试成本漏掉。

## 4. 分阶段详细合同和门槛

### M0：真实任务成本基线

使用明确授权的真实研究任务，保持原目标与规则，记录至少 30 个去重候选的选择方式和完整漏斗。按实际任务收集可交付时间、暂停、来源和失败；任务提前受阻或样本不足时保留结果但不视为达标。离线固定样本应保存允许留存的原始页面或经过校验的引用、采集时间、样本哈希及人工真值；比较同一份输入和冻结政策。真实在线对照单独记录网页、搜索结果、网络和模型的变化，不能把差异全部归因于版本。

指标记录采用版本化报告：`run_id`、release、spec/rule/metrics 版本、配置 hash、采样范围、墙钟和活动时间；候选、准入、可交付与失败计数；来源/阶段耗时及调用数；token 的输入、输出、缓存、来源、统计范围和计费口径。字段无法实测时为 null 和原因；合并或重试必须覆盖完整试验，不把代理字符数称为 token。缓存 token 是输入的子集时不再次相加。首 5 家未达到写未达到；最终未交付时单位成本不可计算。

**门槛 G0：** 固定样本可重放且口径完整；真实任务具备不少于 30 个去重候选的可审计基线，或如实记录不足并保持该门槛未通过；token 的可用性及缺口已明确。不得用估算填补真实 token。G0 未通过时可开发 M1，但不能以 M0 为已完成或宣称真实收益，也不能进入依赖真实对照的正式试点验收。

### M1：候选证据自动整理和校验

1. 建立本地版本化暂存工件，至少包含 run ID、候选 ID、来源 ID、主体、字段、实际值、来源 URL、来源类型、采集时间、方法、原文摘录、可验证的原文引用/哈希及处理状态。发现线索与证据观察分开；搜索摘要只能标记为线索。多主体页面须有条目级边界和定位；不存在可靠边界时标记待核。
2. 离线转换器仅从已观察字段生成现有 EvidenceBundle v2 输入，不补造主体、官网归属、渠道或缺失事实；按现有预检返回每条 `index`、错误码、字段路径与可提交子集。保留完整输入和输出哈希、稳定候选及 chunk 标识；同键同输入可重放，不同输入必须冲突，原子准入不变。状态区分发现、待补证、可预检提交、已准入和待核；预检通过不等于合格。
3. 模型默认读取分页摘要与明确的缺项；支持按候选和来源取回完整有效证据。截断不得破坏主体、事实值、来源或冲突上下文；不足则标记并按需取原文。完整内容遵循现有权限、保留期和清理策略，日志不输出客户排除名单或凭据。
4. 所有导入仍走现有 `validate-input`/`advance` 及交付规则；错误草稿不部分提交。无需为提速改变冻结 run、质量规则或现有 API 默认返回格式。

**门槛 G1：** 受控样本中同页多主体、重复实体、官网不明、冲突、缺原文、过期、恶意或非法输入均能正确隔离或拒绝；前后输入的主体、字段、证据和交付结果等价；中断、重放、并发及过期清理无重复或丢证。固定样本上给出 token 或可观测量对照；无法取得 token 时不宣称 token 节省。G1 通过后才把自动整理接入正式研究路径。

### M2：共享目录统一预算与记账

在运行时核心实现统一预算，而非以 Agent 工具调用数代替。共享列表页计入 run 总页面预算一次，不按同页企业数重复计；企业详情页计入 run 总预算及相应企业预算。页面计量和物理 HTTP/DNS 尝试分别记录；重定向、robots、重试依现有网络观测语义逐次记录，不能将请求数直接等同页面数。缓存命中记录复用及来源，不伪造新访问。跨 run 是否复用及计费必须明确，默认不跨 run 复用。

派发前在同一事务或等效原子机制中检查可用预算并持久化预留；企业抓取与共享目录抓取竞争同一 run 总预算。每次实际发送前沿用现有网络防护和可持久化观察；完成后结算已使用量并释放未使用预留。标识至少包括 run、来源、URL、页面类型、操作幂等键、尝试号、预留及结算状态、时间与结果；同键重放不新增采集或重复扣费，同一页面的真正重新请求依实际尝试计量。中断后依持久化发送记录恢复；发送状态无法确定时保守占用相应预留并报告未知，禁止假定未发送后重复超额派发。预算耗尽停止新派发并保留检查点。

具体页面加载口径、重定向和重试的预算换算须与既有企业页面语义逐项对照并形成版本化合同后实现；历史 run 的原有总量、计数及冻结规则不能静默重算。新能力须由 `capabilities` 明确声明；不支持的旧 run 或无法保证统一计量的外部工具路径安全拒绝自动采集。迁移如需新增 schema，提供升级、备份和经测试的回滚方案。

**门槛 G2：** 在真实 PostgreSQL 隔离测试中验证同页多企业、不同详情页、缓存、重试、重定向、并发争抢最后预算、企业与目录同时派发、宕机各阶段恢复、观测写入失败、暂停及幂等重放；任何情况下不超出冻结总预算，不重扣或漏记。网络防护、robots、域名限速及失败分类不回退；状态能核对预留、消耗、未结算与未知。G2 通过之前目录自动采集功能保持禁用。

### M3：目录批量采集

使用 M2 已验收的统一预算和网络路径，对允许公开访问的静态目录执行有界列表采集和分页，提取条目与明确字段后进入 M1 暂存与校验。记录来源身份、访问和失败、页面及候选数；列表类别和会员身份只作为发现线索。可配置来源、最大页数、深度、时间和每域并发，受 run 预算及原有安全限额约束。无正文、受限、主体不明或证据不足时进入待核或停止；不绕过登录、验证码、robots、429 或其他访问限制。JS 自动渲染不在本规格交付范围。

**门槛 G3：** 固定目录夹具覆盖分页、重复条目、多主体、混合字段、拒绝和中断恢复；核心计数与实际发送记录可核对。真实试点覆盖至少 30 个去重候选、可访问的地方协会和至少一种其他公开来源；环境不足则如实报告且验收未完成。逐项比较主体绑定、资格、渠道、交付集合及人工真值，对所有新增通过项人工检查，存在误通过时阻止发布。使用同口径测首批时间、有效吞吐及可用 token；不具可比性时只报告观察，不归因提速。

### 发布和回滚门槛

完成适用的 G0–G3、现有回归、真实安装入口完整性校验以及冻结 release 验证；文档、能力声明与实际安装结果一致。分别记录安装前后的 release ID 和兼容性；在隔离环境验证旧 run 读取、续跑和导出以及回滚，旧版本不能安全处理新 schema/新 run 时阻止不安全回退并给出已验证恢复路径。只有适用门槛通过才发布对应能力；未交付项在能力声明和结果中标明不可用。版本号按最终发布范围决定，不预先宣称升级完成。

## 5. 范围边界

本方案不改变交付标准、不增加付费数据源、不发送外联、不写 CRM、不绕过访问限制。需求不充分、无法核验或工具不可用时保留未知和检查点。参考：[提速优先实施记录](../IMPLEMENTATION-speed-first-v2.md)、[协会目录规格](SPEC-association-discovery-evidence-v1.md)、[协会目录实施基线](../IMPLEMENTATION-association-discovery-evidence-v1.md)、[实时成果速度记录](../IMPLEMENTATION-live-results-speed-v1.md)。
