## 1. 问题和目标

用户需要在任务运行时看到进度和已找到的客户，同时希望首批结果和整批完成都更快。目前已有 2.2.0 的批量准入、有限并发、网页解析复用和增量导出；现有快照默认按新增可交付数量或时间间隔生成，不能等同于持续可用的客户展示页面。其提速数据主要来自受控测试，不能推断真实任务的完成时间。

本方案目标：

1. 任务运行中持续查看真实进度、已确认客户和待核实项；完成后重新打开仍可看。
2. 让客户名单能直接搜索、筛选、查看证据、复制联系方式和导出。
3. 同时测量并改善首个、首批和整批可交付客户的时间。
4. 保留现有身份、证据、去重、抑制、渠道、预算与来源限制，不以放宽质量规则换速度。

非目标：本阶段不发送邮件或消息，不采购来源，不新增数据库，不建立常驻守护进程，不自动恢复无关任务；不声称客户邮箱或电话已经实际送达。

## 2. 用户场景

- **任务中**：打开某次任务的成果页面，看到当前状态、目标、已准入、已确认可交付、待核实、剩余缺口和最近更新时间；首批客户可出现后续持续增加。
- **找客户**：按公司、业务或城市搜索；按国家、状态和联系方式筛选；点开客户查看匹配理由、联系方式和来源。
- **中断后**：重开同一任务页面，看到最后一次成功更新的内容及其时间；任务是否在运行由已知的实际状态说明，不能用页面打开推断任务仍在运行。
- **交付时**：按当前筛选导出符合原交付政策的 Excel，并显示导出数量和快照时间；待核实项不能混进正式客户名单。

## 3. 页面与交互

### 3.1 顶部：任务和进度

展示任务名称、国家/客群摘要、状态、目标、已用研究时间、最后更新时间和版本。状态至少包括运行中、已暂停、已完成、部分完成、失败/受阻和未知。断开、数据过期或无法读状态时显示“最后更新于……，当前状态未知”，不显示虚假的运行中。

核心数字定义如下；不同指标可能重叠，不做简单相加：

| 页面名称 | 定义 |
|---|---|
| 目标 | 冻结任务的目标企业数；始终使用原目标 |
| 已准入 | 核心已接收的去重前候选数，对应当前 discovered 语义；不得改称全网发现数 |
| 已确认可交付 | 经现行交付选择、去重和抑制后，同时满足冻结客群及渠道政策的企业数 |
| 待核实 | 当前结果中必要事实、主体或渠道仍需确认的企业数，不能计入可交付数 |
| 剩余缺口 | max(目标 − 已确认可交付, 0) |

只有数据源明确提供可靠的 `discovery_seen` 且其统计范围可解释时才另列“已发现”；否则显示“暂不可得”，不把已准入、搜索次数或推测值冒充全量发现。渠道覆盖、完成率和质量统计均标注分子、分母及更新时间；未知为“未知”，不是 0。

有明确失败类别时显示可理解的原因，例如来源拒绝、网络故障、预算耗尽、证据缺失或处理暂停；后台没有报告原因时显示“原因未知”，不根据耗时猜测。

### 3.2 中部：客户列表

默认先显示已确认可交付客户，另有“待核实”视图，并显示各自数量。每条显示企业名称、国家/城市、主营业务或产品、简短匹配理由、已观察到的邮箱/电话/表单、状态及来源入口。没有值时显示“未找到”或“待核实”，不补猜。

提供关键词搜索、国家、状态、渠道筛选，以及最近更新/名称排序。明确提供“清除筛选”和无结果提示。列表默认分页或分段加载；页面显示“当前显示 N 家 / 此筛选共 M 家”。新结果加入时保留用户的筛选、排序、页码、滚动位置和已打开的详情；如有新结果不在当前视图，显示数量提示。不能因自动刷新打断输入、选择文字或复制。

### 3.3 客户详情

点击客户后展开侧栏，窄屏使用全屏详情。展示官网、已知所在地、业务/产品、逐项匹配理由、联系方式、采集时间、证据原文摘录及来源链接。每项能区分“已确认”“待核实”“来源冲突”和“未发现”；解释具体缺项。不同企业共用域名时不能仅因域名相同合并。

复制操作只复制用户选中的公开商务联系方式，并提示成功或失败。官网与来源仅允许安全的 http/https 链接，打开新页时隔离来源页面。公开、来源可追溯不代表已实际验证可送达。

### 3.4 导出和可用性

导出按钮显示当前筛选及将要导出的**可交付**企业数；生成 Excel 后显示文件位置、实际数量和快照时间。筛选包含待核实客户时明确说明这些客户不进入正式交付，必要时单独展示待核实数量；导出后数量由导出结果确认，不用界面预估冒充结果。不得绕过现有交付选择、抑制和去重逻辑。

中文优先；不同状态同时使用文字和颜色。支持键盘操作、可见焦点、屏幕阅读器标签和常见屏幕尺寸。空任务、没有搜索结果、处理中断、无数据和加载失败均有明确提示。页面不自动打开打断用户。

## 4. 实现边界和数据契约

### 4.1 命令与生命周期

沿用 Skill → CLI → 核心 → 文件状态的架构，不把业务判断移到页面，不新增数据库或常驻服务。CLI 提供明确入口生成/打开指定任务的本机页面；打开页面为用户主动操作。任务运行、恢复、完成以及相关结果或权限变更时，由现有有界命令在安全检查点更新页面；命令结束不承诺后台继续采集。

建议第一版由用户手动启动 CLI 的本地查看命令，该命令在前台生命周期内提供仅绑定 127.0.0.1 的临时页面服务；它是短时查看进程，不随系统启动，不自我重启，不负责采集。用户停止查看命令即退出；设置无活动超时并提示，之后可重新启动命令查看已保存的成果。用户主动打开页面，不自动弹窗。运行状态通过既有文件或安全的只读投影获取，不频繁触发带自动维护的 status 命令。处理过程写入临时文件并原子替换，避免读到半份投影；投影无变化时不重复写入。

页面通过本机服务定期读取投影，仅更新变化的区域，保留筛选、滚动、详情和文本选择。用户点击“导出”后，由查看命令调用既有核心导出能力，传递明确的 run 和筛选条件，在核心内重新校验交付政策并返回真实结果；绝不由前端自行判定资格。导出与处理冲突或快照不一致时返回“忙碌/请重试”，不能绕过锁或混用不同时间的计数。页面不得自行触发网络研究、维护、任务状态修改或自动导出。

临时服务使用随机高熵访问令牌，页面、读取和导出请求均须校验；校验 Host、Origin 和请求方法并防护跨站请求及 DNS 重绑定；不启用宽松跨域，不接受任意文件路径或命令。令牌不写日志或外部链接，来源链接不泄露令牌。服务停止或断开时页面明确显示离线及最后更新时间。页面脚本和样式随本机包提供，不依赖外部 CDN 或远程服务。

在处理命令活跃、结果已提交且查看进程正常时，目标为 **5 秒内显示最新已提交变化**；若处理检查点、文件写入或浏览器限制导致滞后，显示真实的最后更新时间和延迟，不用界面动画代替数据。查看进程关闭后不承诺自动刷新；重新打开后应读取最近有效投影。

### 4.2 数据来源和一致性

- 结果、状态、时间和版本来自已提交的核心状态；临时发现池若未持久化或不可可靠读取，不计入核心指标。
- 已确认可交付列表、顶部计数和正式导出复用相同的冻结政策、身份、去重与抑制逻辑；不为界面另造资格判断。待核实列表与正式列表分开，冲突和缺项保留来源。
- 页面数据记录 run 标识、生成时间、任务状态观测时间、数据修订/投影标识、目标、版本及每条证据来源。页面和 Excel 快照时间可能不同，需各自标明。
- 相同 chunk/操作键重放不造成重复客户、计数或页面更新；恢复任务时沿用原 run、冻结配置和已有预算。
- 支持现有 v1/v2 任务各自冻结的政策；缺失字段按未知处理，不用新规则悄悄重判旧任务。
- 抑制、删除、撤销和过期与已有导出生命周期联动，及时重建或撤销本机页面；不能更新或撤销时记录待处理并明确提示旧页面可能过期，不宣称已删除外部复制。禁止把静态页面当成可无限保留的权威副本。

### 4.3 本机数据安全

页面可能包含商务联系人，默认放在既有受管理工件目录内，遵循项目保留及删除规则，不写入 Git 或公共目录。所有来源文本视为不可信输入，按 HTML/脚本上下文安全编码；禁止来源内容执行脚本，阻止恶意链接和表格公式注入。不得将数据库凭据、本机配置或私密环境变量写入页面。输出文件权限继承受保护的本地目录；不自动公开网络访问。

## 5. 速度方案与测量

### 5.1 优先顺序

1. **首个和首批**：事实与官网归属达到准入要求后立即按有界小批提交；首批目标为 5 家证据就绪候选，不等待凑满 20 家。显示已提交的真实结果，候选不因进入页面自动成为合格客户。
2. **整批吞吐**：在来源和工具允许范围内批量执行独立搜索、读取高信息密度来源，并在现有预算、限流和最大 worker 上限内交错发现与补证。优先复用已有证据和已读页面，满足渠道政策后停止不必要请求。
3. **根据瓶颈改动**：分别观察 Agent 搜索、页面等待、准入/资格、补渠道、数据库、页面生成和导出；先处理测得最慢环节。禁止通过减少目标、放宽事实证明、绕过 robots/限流或掩盖失败制造提速。
4. **分段交付**：在不改变原目标和口径的前提下，持续提供符合规则的增量结果，最终导出仍以同一政策为准。

### 5.2 指标与验收方法

同一任务口径记录实际起点、暂停时长、首个已确认可交付客户、首批 5 家可交付客户、每新增 10 家及整批达到目标或终止的时间。分别报告墙钟时间与扣除明确暂停后的活动时间；不足 5 家或未完成则写“未达到”和实际原因。记录已发现（确实可测时）、已准入、合格、可联系、缺证、重复、失败、来源拒绝、工具调用、核心实际 HTTP 请求数，以及各阶段耗时；无法直接观测时填未知。

使用相同输入、证据、政策、预算、来源条件和机器，分别测量 2.2.0 基线与新版本：先做可复现的受控测试，再在用户明确给定的真实任务上进行对照。真实网页或搜索结果不可完全复现时说明差异，避免把不同任务的耗时直接归因于代码。每次记录目标数量、有效交付数量、首批及最终耗时、错误率和数据质量；不得把页面展示延迟当成采集耗时。当前没有可复现的真实业务基线，正式速度目标在基线测量后确定；不可先承诺固定倍数。

## 6. 验收标准

| 编号 | 必须满足 |
|---|---|
| AC-01 | 页面明确展示冻结目标、已准入、可交付、待核实、缺口、真实任务状态和各自更新时间；未知不会被显示为 0 或运行中。 |
| AC-02 | 在运行中逐条或小批看到已提交客户；自动刷新或手动刷新机制按目标浏览器实际能力工作，交互不中断，断线/滞后清晰可见。 |
| AC-03 | 搜索、筛选、排序、分页、复制、链接及详情在桌面和窄屏可用；无结果、失败和空任务有提示。 |
| AC-04 | 客户事实、联系方式、缺项和来源可追溯；不推测邮箱，不把待核实客户计为可交付。 |
| AC-05 | 同一时点同一条件下，页面可交付数量、核心选择和正式导出一致；筛选导出数量及快照时间可核对；去重、抑制、撤销、过期生效。 |
| AC-06 | 页面内容正确转义，不执行来源脚本，不泄露凭据；无远程依赖，临时服务仅本机访问并校验令牌，输出位于受管理的本机目录。 |
| AC-07 | 页面生成中断后不产生半页；恢复、chunk 重放、暂停、完成和失败状态可正确呈现；不新增常驻进程。 |
| AC-08 | 提供可复现的基线和新版本首个、首批、整批耗时及质量报告；达不到目标如实报告，不根据受控结果宣称真实任务达标。 |
| AC-09 | 现有测试及针对计数一致性、筛选导出、状态变更、转义、恢复和交互的必要测试通过；数据库测试不得将跳过算通过。 |
| AC-10 | 至少一次真实使用场景下，由用户检视：能迅速找到客户、理解匹配理由、复制联系方式并查看来源；记录问题和处理结果。 |

## 7. 实施顺序与发布

1. **基线与投影**：冻结 2.2.0 对照，定义页面数据契约和与导出共用的选择入口，补计时和一致性验证。
2. **可用页面**：实现进度、客户列表、详情、筛选、导出入口、空/异常/滞后状态和本机文件生命周期。
3. **有针对性的提速**：依据基线处理首批和整批瓶颈；保留预算、证据和来源约束。
4. **验收与发布**：运行测试、完成受控对照和真实使用检视，记录已知缺陷；通过后再统一更新产品版本、发布清单和安装记录，保留 2.2.0 冻结发布及回滚路径。回滚前确认数据库 schema 兼容，不能只回退界面文件。
