# 模块边界与数据流

## 调用关系

`Skill → CLI → runs → pipeline → rules + web`。`runs` 通过 `persistence` 存储结果，导出时调用 `delivery`。所有模块位于同一 Python 包，使用函数调用。

- `cli`：读取 JSON 和命令行参数，校验输入并返回 JSON，不做资格或交付判断。
- `runs`：冻结客群要求，接收每轮证据，管理任务、检查点、时间、租约、重试、幂等和导出记录。
- `pipeline`：资格预判、最多两页确认、合格后有限补齐、联系目标早停、评分；返回结果与页面尝试，不读写数据库。
- `rules`：资格、联系方式、评分各自独立。默认不访问网络，MX 查询由调用者注入。
- `web`：只读取页面或执行 DNS/MX 查询；URL 检查不触发 DNS。观测通过注入 sink 写入，网页模块不依赖数据库。
- `delivery/selection`：公共去重、抑制、渠道过滤、证据核对、交付选择。
- `delivery/metrics`：计算明确分母的质量和请求指标。
- `delivery/exporting`：把统一选择结果编码为 Excel/CSV 和 manifest，不定义另一套交付规则。
- `persistence`：数据库模型与事务、不可变文件、过期与撤销文件操作、备份恢复。

## 一家企业如何流转

1. Skill 在公开页面确认企业身份、客群适配与渠道证据，追加候选与检查点。
2. runs 校验 chunk 幂等、证据和候选上限，生成独立企业任务。同域不同实体保留冲突，不仅按域名合并。
3. process 用短事务领取任务并写入租约；释放行锁后执行网络访问，期间延长租约。
4. pipeline 明确排除时零抓取；待确认时最多读取两页；合格后复用页面继续抓取，合计最多十页。失败也占页预算。
5. contacts 通过注入的 MX 查询规范和验证渠道，ranking 计算分数。
6. runs 在短事务中再次核对执行令牌和租约，保存企业、快照和消耗；旧执行者不能覆盖恢复后的结果。
7. status 与导出使用同一交付选择。export 生成四表，保存带哈希的文件和质量报告，返回绝对路径。

## 状态、幂等与维护

- 每个 run 冻结一份客群配置，无独立客群版本或来源目录管理。
- create 同 run、同 spec 可重放；append 使用 chunk；process 可显式指定 operation-key；export 支持具名快照。操作账本与业务写入处于同一数据库事务。
- 处理被中断后，保留输入和原操作键重试；过期租约可回收。pause 停止研究计时，resume 后继续。
- finish 关闭候选输入，有限处理剩余任务；仍有队列时继续 process。
- 默认导出根据实际交付投影刷新；具名 export-key 维持快照。新增抑制或删除企业撤销相关旧文件。
- 没有常驻 worker。每次命令执行数据库节流维护，另提供 maintenance 预览/apply。进程全部停止期间不执行清理，下次调用补做。

## 数据与兼容边界

使用 PostgreSQL 的 JSONB、事务锁与持久租约；不切换 SQLite。新表统一使用 skill_ 前缀。原始快照和导出采用独立文件目录及不透明键。

skill_v2_002 通过增量迁移加入主机限流、robots 规则缓存、文件删除待办及导出报告哈希。Web 通过注入的回调访问限流/缓存，不导入数据库模块。文件删除待办与业务撤销同事务提交，提交后重试物理删除。已知 skill_v2_001 可保留数据升级，其他旧系统数据库仍被拒绝。

旧前端、API、认证、地图/模型适配器、产品画像、旧队列和部署配置退出工作树，完整源文件已归档。新旧数据库互不升级；旧版本恢复需使用归档代码与原库。数据库不可用、证据不足和来源拒绝均保留明确结果，不伪造渠道或完成数量。
